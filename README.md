# BACCHUS-SYSTEM

日本酒のラベル写真・保管場所・残量を管理するモバイル向けPWA。iPhone/Androidのブラウザから使えます。バージョン 0.3.0。

## 実装した機能

- 写真撮影・端末内で縮小、銘柄・酒蔵・容量・製造年月等を確認して登録
- Gemini・Claude・OpenAIから選べるAIラベル読み取り（サーバーのAPIキー・モデル設定が必要）
- 複数冷蔵庫と自由入力の棚・区画、瓶単位の移動
- 300mlは1本消費、その他は1合＝180ml消費。端数は「残りを飲み切る」
- 開封日、残量、入荷・消費・移動履歴、後続変更がない操作の取消
- 銘柄・酒蔵検索、冷蔵庫フィルター、空瓶表示
- 個人用：IndexedDBに在庫・写真・履歴を保存、オフライン登録・検索
- 共用：認証付きAPI・サーバーSQLite。テナント（店舗・会社・家族など）ごとに在庫を分離し、テナント内の利用者で共有
- 全体管理者・テナント管理者・メンバーの3ロール。画面からテナント作成、利用者追加、トークン発行・再発行・失効
- 冷蔵庫の追加・名前変更・削除（共用ではテナント管理者のみ）
- オフラインの共用操作は端末に保留し、通信復旧・更新・同期操作で再送
- 操作IDによる重複防止、瓶のversionによる競合検出、サーバーで操作と履歴を同時保存
- JSONバックアップ、個人用バックアップの検証付き復元
- 個人用から共用への在庫コピー（冷蔵庫・写真・開封日・残量、重複防止付き）

初期データは空です。「冷蔵庫」→「＋冷蔵庫」→「撮影して登録」で始めます。AI解析は任意で、手入力のみでも全在庫機能を使えます。

## 起動（Python 3.12以降、外部パッケージ不要）

```sh
git clone https://github.com/UeEmon/BACCHUS-SYSTEM.git
cd BACCHUS-SYSTEM
python3 -m server.app
```

PCで http://127.0.0.1:8000 を開きます。公開リポジトリのcloneにはGitHub認証は不要です。未設定でも個人用モードが動作します。

## Docker Desktop

```sh
cp .env.example .env
docker compose up -d --build
```

PCで http://localhost:8092 を開きます。`.env`は自動生成されないためコピーしてください。DBは`bacchus-data`ボリュームに保存します。`docker compose down -v`はDBを消すため通常は使いません。

## スマートフォンで使う

PWAのオフライン起動とホーム画面追加には、信頼された証明書によるHTTPS配信が必要です。PCのlocalhostに対する開発用例外は、携帯電話からPCのLANアドレスへアクセスする場合には適用されません。

1. サーバーの前段にHTTPSリバースプロキシを配置し、スマートフォンからアクセスできるホスト名を用意します。
2. バックエンドの8000（Dockerでは8092）へプロキシします。アプリとAPIは同じオリジンです。
3. iPhoneはSafariでアクセスし「共有」→「ホーム画面に追加」。Androidはブラウザのインストール機能を使用します。
4. 初回オンライン起動後にオフライン起動を確認してください。ブラウザのデータ削除で端末在庫・保留操作は消えます。

LAN上の別PCから開発確認する場合は`HOST=0.0.0.0 python3 -m server.app`、Dockerなら`.env`の`BIND_ADDRESS=0.0.0.0`を指定します。HTTPのLAN接続は画面確認用です。共用トークンや写真を送る運用はHTTPSで行ってください。

## 共用保存・AI設定

Python直接起動時は環境変数を設定してください（`.env`を自動ロードするのはDocker Composeのみ）。

```sh
python3 -c 'import secrets; print(secrets.token_urlsafe(32))'
```

生成したトークンを`.env`の`BACCHUS_USERS`に**最初の全体管理者**として登録します。以降のテナントと利用者は画面から作成します。

```dotenv
BACCHUS_USERS='{"24文字以上のランダムなトークン":{"name":"運営","role":"system_admin"}}'
GEMINI_API_KEY=Googleで発行したAPIキー（画面から設定する場合は不要）
GEMINI_MODEL=アカウントで利用可能な画像入力対応モデル名
# ClaudeやOpenAIを環境変数で使う場合（任意）
AI_PROVIDER=claude
ANTHROPIC_API_KEY=Claude Consoleで発行したAPIキー
ANTHROPIC_MODEL=claude-opus-5-5
OPENAI_API_KEY=OpenAI Platformで発行したAPIキー
OPENAI_MODEL=gpt-5.5-mini
```

`AI_PROVIDER`は`gemini`（既定）・`claude`・`openai`のいずれかです。

`docker compose up -d`で設定を反映し、アプリの「設定」でトークンと保存先を指定します。

### テナントとロール（共用モード）

在庫（冷蔵庫・瓶・履歴）はテナントごとに分かれ、他のテナントからは見えません。利用者はいずれか1つのテナントに所属します（全体管理者はどのテナントにも所属しません）。

| ロール | `role` | できること |
|---|---|---|
| 全体管理者 | `system_admin` | テナントの作成・名前変更、全テナントの利用者の追加・削除・トークン再発行、全体管理者の追加、AI設定（全テナント共通） |
| テナント管理者 | `tenant_admin` | 自テナントの在庫のすべての操作、冷蔵庫の追加・名前変更・削除、個人用在庫の一括追加、自テナントの利用者（テナント管理者・メンバー）の追加・削除・トークン再発行 |
| メンバー | `member` | 自テナントのすべての冷蔵庫での登録・消費・飲み切り・移動・取消、AIでのラベル読み取り |

**始め方**: 全体管理者のトークンで接続し（保存先は「個人用」のまま）、「設定」→「利用者・テナントの管理」でテナントを作成し、テナント管理者を追加します。表示されたトークンを本人に渡すと、本人は保存先「共用」で接続し、冷蔵庫とメンバーを追加します。全体管理者はテナントの在庫を見たり操作したりしません。

**トークン**: 画面で発行したトークンは発行時に1回だけ表示し、サーバーにはSHA-256ハッシュだけを保存します。紛失したら再発行してください（古いトークンは即時に無効）。利用者を削除するとそのトークンは使えなくなり、操作履歴の名前は残ります。自分自身は削除できません。

**冷蔵庫の削除**: 在庫が残っている冷蔵庫は削除できません（先に移動します）。空瓶の記録は「削除済みの冷蔵庫」として残ります。

権限はすべてサーバーで判定し、許可されない操作はHTTP 403で拒否します。画面上部にテナント名とロールを表示し、権限のない操作のボタンは表示しません。個人用モードは端末内の利用のためロールはなく、冷蔵庫の管理もできます。

**`.env`の利用者**: `BACCHUS_USERS`の利用者は画面から変更・削除できません（変更は`.env`を編集して再起動）。`system_admin`以外は「既定のテナント」に所属します。値が表示名だけの`"トークン":"利用者名"`と、以前の`"role":"admin"`はテナント管理者、`role`を省略した`{"name":"…"}`はメンバーです。商用運用では`.env`には全体管理者だけを置き、他は画面で管理することを推奨します。

### AIサービスとAPIキーを画面から設定する

全体管理者の接続トークンを設定したあと、「設定」→「AIラベル読み取り」でAIサービス（Google Gemini・Anthropic Claude・OpenAI）を選び、APIキーを入力して保存します。最後に保存したサービスがラベル読み取りに使われます。キーはサービスごとに別々に保存するため、切り替えのたびに入力し直す必要はありません（キー欄を空のまま保存すると保存済みのキーを使います）。環境変数だけで設定したサービスも、キー欄を空のまま保存すると切り替えられます。

保存時にサーバーがそのキーで使えるモデルの一覧を取得します。モデルが「自動（推奨）」のときは、ラベルの文字を読める（画像入力に対応した）モデルの中で**最も速く安価な系統の最新版**を選びます。ラベル読み取りは文字認識（OCR）が中心で、軽量モデルで足りることが多いためです。読み取り精度が悪い場合は、設定画面のモデル一覧（速く安価な順）から高性能なモデルを選んで保存してください。読み取り完了時の表示に使用したモデル名が出ます。

- **Gemini**（Google AI StudioのAPIキー）: 最新の安定版Flash-Lite → Flash → Pro。安定版がなければプレビュー版。
- **Claude**（Claude ConsoleのAPIキー）: 画像入力と構造化出力（JSONの形式保証）に対応した最新のHaiku → Sonnet → Opus。4.5世代より前は対象外です。対応モデルでは思考量を`low`に抑えます。Sonnet・Opusの一部では、安全上の理由で断られた場合にサーバー側の代替モデル（`fallbacks`）で再試行し、それでも断られたら手入力を案内します。
- **OpenAI**（OpenAI PlatformのAPIキー）: GPT-4.1以降の最新のnano → mini → 通常版。

どのサービスでも一覧から特定のモデルを選べます。自動選択中に使用中のモデルが提供終了（HTTP 404）になった場合は、その時点の最適なモデルを選び直して1回だけ再試行します。

キーはサーバーのSQLiteの設定領域に保存し、在庫データ（`/api/state`）やJSONバックアップには含めません。画面には末尾4文字だけを表示します。DBファイルのバックアップにはキーが含まれるため、非公開の場所に保管してください。画面で設定したキーは同じサービスの環境変数（`GEMINI_API_KEY`・`ANTHROPIC_API_KEY`・`OPENAI_API_KEY`とモデル名）より優先し、画面で削除すると環境変数の設定に戻ります。AI設定は全テナント共通で、変更できるのは全体管理者だけです（AIの利用料金は運営側のAPIキーに請求されます）。テナントの利用者は全員AI読み取りを使え、設定状態を閲覧できます。接続トークンは端末のsessionStorageに保存し、サーバーAPIキーは端末に配布しません。冷蔵庫ごとの閲覧・利用制限、閲覧専用ロール、テナントの削除、テナントごとのAI利用量の上限は未実装です。

AI解析はユーザーが「AIでラベルを読み取る」を押したときだけ、写真をサーバー経由で設定中のサービス（Google・Anthropic・OpenAIのいずれか）へ送信します。個人用保存でもAI利用時には画像が送信されます。個人用の在庫DB全体を送ることはありません。APIの認証・課金・利用上限はチャットサービスの契約とは別です。

APIリファレンス: https://ai.google.dev/api/generate-content ・ https://platform.claude.com/docs/en/api/messages ・ https://platform.openai.com/docs/api-reference/chat

### 同期・競合

共用モードではサーバー接続後に利用します。オフライン時は前回のデータと保留操作を表示します。同期はアプリが開いている間に実行され、OSによるバックグラウンド実行は保証しません。同じ瓶を別端末で変更すると保留操作は競合として残り、勝手な上書きはしません。「同期」で再試行し、解消できない場合はバックアップ後に「保留操作を破棄して再取得」を選び、正しい操作を入力し直してください。

保存モードを切り替えても個人データと共用データは別々に保持します。共用モードの「設定」→「個人用の在庫を共用へ追加」で、端末の冷蔵庫・瓶・写真・開封日・残量をコピーできます。確認画面で共有対象を確認して実行します。既に移行した瓶は上書きせず、移行元も残します。過去の操作履歴は個人用に残り、共用には移行記録を追加します。冷蔵庫はIDで区別し、同名の異なる冷蔵庫を自動統合しません。1回の上限は100冷蔵庫・1,000本・約20MBです。移行後の二方向同期、共用から個人への移行、共用JSONのアプリ内復元は未実装です。共用DBはサーバー停止中にボリュームをバックアップするか、SQLiteのオンラインバックアップ機能を使ってください。復元時はサーバー停止中にDBを置き換えます。

## 構造

| 層 | ファイル | 責任 |
|---|---|---|
| 画面 | `web/app.js`, `index.html`, `styles.css` | 入力・表示・ユーザー確認 |
| ドメイン | `web/domain.js`, `server/domain.py` | 容量・消費ルール・変更検証 |
| 端末/共用保存 | `web/repositories.js` | IndexedDB、API、保留操作 |
| サーバー保存 | `server/repository.py` | テナント・利用者・在庫のSQLite保存とトランザクション |
| 利用者・権限 | `server/accounts.py` | 認証、ロールごとの権限、テナント・利用者管理、トークン発行 |
| AIアダプター | `server/recognition.py` | Gemini・Claude・OpenAIへの画像送信・モデル選択・結果検証 |
| HTTP | `server/app.py` | 認証、静的配信、API |

`InventoryService`, `Bottle`, `ConsumptionPolicy`, `LocalRepository`, `ServerRepository`, `RecognitionService`, `LabelRecognizer`（サービスごとの`Gemini`・`Claude`・`OpenAI`）の責任を分離しています。表示に必要な値は容量mlを整数として保持し、数量と残量を混同しません。商品ごとに瓶の個体IDを発行するため、同銘柄の開封済み瓶・別の冷蔵庫の瓶も区別できます。

初版はネイティブFlutterではなくPWAであり、端末保存はSQLiteではなくIndexedDBです。サーバーは小規模共用向けのSQLite状態ストアで、テナントごとに在庫全体を1行のJSONとして保存します。商用で多数のテナントや大量の在庫を扱う場合は、商品・瓶・履歴を正規化したDBとページングへ変更してください。

## 0.3.0 更新

AIラベル読み取りにClaudeとOpenAIを追加し、共用モードをテナント単位に変更しました。

**既存環境の移行**: 初回起動時に、それまでの共用在庫は自動で「既定のテナント」へ移ります（端末の保留操作もそのまま同期できます）。`.env`の既存利用者はこのテナントのテナント管理者になります。AI設定とテナント作成には全体管理者が必要なため、`BACCHUS_USERS`に`{"name":"運営","role":"system_admin"}`のトークンを1つ追加してください（全体管理者がいない場合は起動時に注意を表示します）。DBの形式が変わるため、更新前にDBをバックアップしてください。既存のGemini設定はそのまま引き継がれます。自動選択は最も速く安価な系統（GeminiはFlash-Lite）に変わりました。既存の自動選択中のGeminiは、設定画面でAI設定を保存し直すと切り替わります（保存し直すまでは従来のモデルを使います）。既存のDocker環境は `git pull --ff-only` → `docker compose up -d --build` で更新します。PWAを開いたままの場合、新しいオフラインキャッシュは既存のアプリタブをすべて閉じて開き直すと有効になります。在庫データは保持されます。
